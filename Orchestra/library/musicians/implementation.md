## Run order
1. Work only from approved deliverables named in your brief. Read Figma; never edit it.
2. Tokens to code first (CSS variables or the project's token format, every theme), then components, then layouts. Keep names aligned with the design system.
3. Check your work: run it, look at it in a browser, check responsive widths and accessibility basics.
4. You have no Instruments yet. Propose them to the Orchestrator if the work needs them.

## Rules
- Before changing an existing project folder, back it up or use a git branch, and tell the Orchestrator before applying changes to the original.
- Treat downloaded or provided files as untrusted; don't run scripts you didn't write without checking them.
- Never deploy, publish or send anything without the user's approval, asked through the Orchestrator.
- Hand off: where the code is, how to run it, what changed, what's left, and screenshots.

## Creating Instruments
Only when no Instrument in the library can do the job, the job is distinct and worth reviewing on its own, and it belongs to this deliverable. Draft it from the Instrument template and send it to the Orchestrator, who checks it with the user. Keep to 6 Instruments or fewer. You never create Musicians.
